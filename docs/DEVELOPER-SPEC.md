# Akif's Special YouTube Addon — Developer Spec

This is the binding contract for everyone implementing a part of the project. Read it fully before writing code.
Sections marked **(owner: X)** say which module implements what. Shared foundation files already exist — **use them, do not rewrite them**. If a foundation file has a bug or is missing something you need, make the smallest possible fix *and report it* in your final answer.

---

## 0. Ground rules (all modules)

1. **Plain JavaScript, no build step, no npm dependencies in `extension/`.** Classic scripts (no `import`/`export`) that attach to the global `AYT` namespace: `(function (g) { 'use strict'; const AYT = g.AYT; ... })(globalThis);`
2. **Never use `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write` or `DOMParser` for UI.** YouTube enforces Trusted Types. Build DOM with `AYT.dom.h()` / `AYT.dom.icon()`.
3. **Every user-visible string goes through `AYT.t('module.key', params)`.** Put the English text in `i18n/parts/en.<module>.json` (create your own part file; one JSON object, keys sorted, `{name}` placeholders). Reuse existing `common.*`, `job.*`, `host.*`, `toolbar.*`, `error.*` keys from `i18n/parts/en.core.json` (do not edit that file). Key naming: `<module>.<camelCaseName>`. Do NOT write translations — a later step translates English into az/tr/ru/fr/de/es. Keep strings short and natural; no string concatenation of translated fragments (use placeholders). A text with a count uses a plural key (§3); numbers, sizes and percentages go through `AYT.util.format*` (never `n + '%'`).
4. **Styling:** use the design-system classes in `extension/shared/ui-styles.js` (`ayt-btn`, `ayt-select`, `ayt-row`, `ayt-badge`, `ayt-notice`, ...) and components in `extension/shared/ui.js`. Colours only through the tokens (§3): `--ayt-accent-text` for red text, `--ayt-focus` for focus rings. Module-specific CSS goes through `AYT.ui.addStyles(cssString)` at module load (class names prefixed `ayt-<module>-`). Page-level CSS (affecting YouTube's own DOM) goes in `extension/content/page.css`, gated by `html.ayt-<name>` classes toggled with `AYT.pageClass.set(name, bool)`.
5. **Errors:** catch everything in event handlers; show friendly messages via `AYT.ui.toast(text, {kind:'error'})` or `AYT.ui.notice(...)`. Never leave a spinner forever — use timeouts.
6. **Security:** data from the page's MAIN world (`AYT.bridge`) and from YouTube is untrusted. Never build file paths, URLs for `chrome.downloads`, or native-host arguments from it without validation. Only `*.youtube.com`, `youtu.be`, `*.ytimg.com` URLs are ever fetched/downloaded. Native host arguments are passed as an argv array (never through a shell). Our shadow roots are open, so page scripts can read and drive them: never put the absolute save path (it contains the Windows user name) into text, `title` or `aria-*`, and show host / yt-dlp texts that can name a file (job errors) only through `AYT.util.hidePaths` (§3); never trigger behaviour with `el.click()` / `dispatchEvent` inside our roots (`AYT.keys.guard` drops script-made events); privileged handlers not built with `AYT.ui.button` check `AYT.keys.trusted(e)`.
7. **Performance:** no busy polling faster than 250 ms; disconnect observers/timers when a panel closes; content scripts run on every YouTube page.
8. **Robustness against YouTube SPA navigation:** the same `<video>` and many elements are reused between videos; always re-query; react to `AYT.page.onChange`.
9. Code style: 2-space indent, single quotes, semicolons, small functions, JSDoc on public functions. Comments in English.

## 1. Architecture

```
YouTube tab
 ├─ content/main-world.js   (MAIN world) player API + player response + captions access + history hooks
 │        ⇅ window.postMessage bridge (AYT.bridge)
 ├─ isolated content scripts (shared/* + content/*)
 │    toolbar above the title · panels (portal layer) · tools · Shorts button · page.css classes
 │        ⇅ chrome.runtime messages + 'ayt-ui' port (AYT.client)
Service worker (background/*)
 │    jobs queue/state (history in IndexedDB) · chrome.downloads for browser-side files · notifications · context menus · commands
 │        ⇅ Native Messaging (com.akif.youtube_addon)
Companion host (companion/host/host.ts run by Deno via host.bat)
      yt-dlp (+ Deno as its JS runtime) + ffmpeg  → files in the user's Downloads folder
```

* Browser-side features (no companion needed): screenshot, thumbnail download, subtitle download (in-browser path), all player tools, hide comments & other cleanup.
* Companion features: video (up to 8K/HDR) and audio downloads, clips/GIF, playlists, subtitle fallback.

Extension ID is fixed by the manifest `key`: **`oicpmbpfimnoolnhfgdocfjelknjlcif`**. Native host name: **`com.akif.youtube_addon`**.

## 3. Foundation APIs (already implemented — read the source for details)

* `AYT.util` (shared/utils.js): `clamp, sleep, uuid, debounce, throttle, formatBytes, formatSpeed, formatPercent, formatDuration, formatClock(sec, withMs), parseClock(text), formatEta, languageName(code, fallback), formatName(code), jobLabel(job), hidePaths(text), resolutionBadge(shortSide), sanitizeFilename(name, max), buildFilename(style, {title,id,author,date}, ext, suffix), downloadsPath(subfolder, filename), videoIdFromUrl, playlistIdFromUrl, isMixPlaylist, watchUrl, playlistUrl, bytesToBase64, blobToDataUrl, textToDataUrl, dataUrlToBlob, escapeXml`.
  * Numbers follow the UI language (Intl). `formatBytes(bytes)` / `formatSpeed(bytesPerSec)` → `679.3 MB` / `2.4 MB/s` (fr `679,3 Mo`, ru `679,3 МБ`; English keeps B/KB/MB/GB/TB); the next unit (÷1024) starts before the number would reach 1000 (never "1,011 MB"); no decimals for B/KB, at most 1 for MB, 2/1/0 for GB+ (`2.01 GB`, `25.0 GB`, `150 GB`); `''` when unknown. `formatPercent(p)` takes 0..100 and rounds (`42%`, fr `42 %`, tr `%42`; pass `Math.floor(p)` for progress).
  * `languageName(code, fallback)` → the language's name in the UI language, capitalized (`'tr'` → "Turkish"); when the UI language has no name for it (Chrome's Azerbaijani names only Azerbaijani itself), `fallback` (e.g. YouTube's own track name), then the English name, then the code (no code → `fallback` or `''`). `formatName(code)` → `'opus'` → "Opus", `'vtt'` → "WebVTT".
  * `jobLabel(job)` → the job's label rebuilt from `job.task` in the current UI language: video `MP4 · 2160p60 · HDR · Turkish · Playlist`, `WebM · 1080p · ✂ 01:00–02:30` or `MP4 · Best quality` (resolution = YouTube's step for the task's width × height), audio `MP3 · 192 kbps · ✂ …`, subtitle `SRT · English ⚙︎ → Azerbaijani`, gif `GIF · 480px · ✂ …`. It returns `job.label` (the text the UI sent at creation) for a job without a task, when the task left the container or MP3 bitrate to the settings and the finished file's extension can't tell it, and when the UI language has no name for the job's language (`audioLang`, or a subtitle job's `subLang` / `subTranslateTo`): the panels wrote that label with YouTube's own name for it. Without a `job.label` such a language gets its English name. Job rows and notifications show it, so their text can differ from `job.label`.
  * `hidePaths(text)` → `text` with every absolute Windows path (drive or UNC, also `\\?\` and `\\?\UNC\`, which counts as `\\server\share\…`, with single or doubled backslashes or `/`) cut to its last name (`Permission denied: 'C:\\Users\\jdoe\\Videos\\a.mp4.part'` → `Permission denied: 'a.mp4.part'`); a path of at most three parts (drive or server included), whose last name could be the user's own folder (`C:\Users\<name>`, `\\server\share\<name>`), becomes `…`. URLs and relative paths stay; running it twice changes nothing. The one path-hiding rule (§0.6): the service worker's `job.error` (§7.3) and `AYT.ui.jobItem`'s error line both use it.
* `AYT.i18n` / `AYT.t(key, params)`: `language`, `onChange(fn)`, `setLanguage(pref)`, `resolve(pref)`, `has(key)`, `pluralCategory(count, lang?)`, `SUPPORTED`. The `language` setting defaults to `'en'` (English is the extension's main language, as the owner asked); `'auto'` is a choice in the language selects. `'auto'` = the first entry of `navigator.languages` (Chrome's preferred languages) whose base language is supported, then `chrome.i18n.getUILanguage()`, then English (Chrome has no Azerbaijani UI, so the preferred list comes first).
  * **Plural keys:** when `params.count` is a finite number, `t()` uses `<key>.<category>` with the category from `AYT.i18n.pluralCategory(count)` (`Intl.PluralRules`), then a plain `<key>` (a count-safe text), then `<key>.other`, then the same in English. English part files define `<key>.one` + `<key>.other`, never a plain `<key>` next to them; a translation gives every form its language needs (build-i18n prints them, e.g. ru one/few/many/other) or one count-safe `<key>`. Texts with other numbers (`{done}`, `{failed}`) must be count-safe ("Downloaded: {done} · Failed: {failed}").
* `AYT.settings`: `load()` (reads only the `settings.*` keys), `get(name)`, `all()`, `set(name, v)`, `setMany(obj)`, `reset()`, `export()`, `import(obj)`, `onChange(fn(changes, all))`. Names/defaults: `AYT.DEFAULT_SETTINGS` in constants.js. Adding a new setting = add it to DEFAULT_SETTINGS (report it).
* `AYT.dom`: `h(tag, props, ...children)`, `s()` (SVG), `icon(name, {size, strokeWidth, className})`, `registerIcon(name, def)`, `clear(el)`, `render(el, ...children)`. Icon names: see `ICONS` in dom.js.
* `AYT.ui` (shared/ui.js):
  * `button({label, icon, variant:'primary'|'ghost'|'danger', size:'sm', block, title, ariaLabel, className, onClick, disabled})` (a visible label is the accessible name and `title` its description; icon-only buttons are named by `title`), `select({options:[{value,label,disabled,group,lang}], value, onChange, ariaLabel, disabled})→{el, select, value, setOptions}` (`lang` = the language the label is written in), `segmented({options:[{value,label,icon,title,disabled}], value, onChange, ariaLabel})→{el,value}` (radio group: ←/→ select the next enabled option), `radioList({options:[{value,label,desc,disabled}], value, onChange})→{el,value,setOptions}`, `switchControl({label, desc, checked, disabled, onChange})→{el,input,checked}`, `slider({min,max,step,value,format,onInput,onChange})→{el,value,setBounds}`, `rangeSlider({min,max,step,start,end,minGap,format,onInput,onChange})→{el,start,end,set,setBounds}`, `timeInput({value,min,max,withMs,onChange,ariaLabel})→{el, errorEl, value, setMax}`, `textInput({type,placeholder,value,onChange,onInput,ariaLabel})→{el,value}`, `progress({value})→{el, set, setState('done'|'warn'|'error'|null)}` (`warn` = finished with problems: amber bar), `badge(text, variant)`, `notice({kind, title, text, icon, children, actions:[{label, icon, variant, onClick}]})`, `spinner()`, `field(label, control, hint)`, `mountStyles(root, css)`, `addStyles(css)`, `applyTheme(el)`. * `AYT.keys` (content scripts only):
  * `isolate(root, onEscape, {pass})`: key events from inside `root` don't reach YouTube's shortcuts; an Escape keydown goes to `onEscape(e)` first (returning `false` = not handled); `pass(event, target)` → true lets that key event through (`target` = innermost element). * `AYT.toolbar`: `register(def)`, `get(id)`, `list()`, `open(id, opts)` (as if used from the keyboard; `opts.viaKeyboard === false` opens a panel like a mouse open, for the popup's link clicked with the mouse; a panel that is already open stays as it is), `close()`, `toggle(id)`, `isOpen(id)`, `refresh()`, `flash(id)`, `renderPanelInto(id, container, extras)`. The button `def` (header comment of toolbar.js): `{id, order, group:'download'|'tools'|'end', icon, title, panelTitle?, panelIcon?, panel?:{width, render(ctx), selfFit?}, onClick?(ctx, event), isOn?, ariaPressed?, badge?, badgeLabel?(value), progress?, surfaces, commands}`.

Attributes are written only when they change.

The Shorts popover passes no `viaKeyboard`.
  * Without `panel.selfFit: true` the toolbar caps an open panel's height to the visible space (`--ayt-panel-h`; the body scrolls) and scrolls the page once when the content needs room; it backs off when something else writes `--ayt-panel-h` (`AYT.dl.fitPanel`). `refresh()` never measures the layout: an open panel follows its button through ResizeObservers on the toolbar host, the player, the toolbar's column `#below` (YouTube fills its alert, info-panel and shopping-shelf slots above the toolbar late, e.g. `#alerts`, `#clarify-box`, `#shopping-timely-shelf`, while `<html>` and `<body>` stay 0 px tall) and `<html>` (scrollbar width), set up again when the toolbar is re-mounted; it is also placed again on window resize, button re-render, a toolbar re-mount and a page change.
  * Keyboard: an ARIA toolbar with one Tab stop (←/→/Home/End move between buttons); other keys (k/j/l/f/m, digits) still reach YouTube; Escape closes a panel and returns focus to its button.

## 5. VideoInfo (content/video-info.js)

Verified facts (Nov 2026, real watch pages): the web player response has `streamingData.adaptiveFormats` with full metadata (`itag, mimeType, width, height, fps, qualityLabel` like `"4320p60 HDR"`, `contentLength` present on all formats, `colorInfo`, `audioTrack {displayName, id:'ar.3', audioIsDefault}`, `xtags`, `isDrc`) but **no URLs** (`serverAbrStreamingUrl` only → SABR). There are usually no muxed `formats`. 8K example `1La4QzGeaaQ` has only an HDR 4320p (AV1, itag 702, ~2.1 GB); SDR and HDR variants co-exist for lower heights (VP9 `vp9` vs `vp9.2`, AV1).

  audioTracks: [{ id, lang, name, isDefault, isOriginal }],   // only when there are 2+ tracks; original first
  captions: { tracks: [{ lang, name, kind, isAuto, vssId, isTranslatable }], translationLanguages: [{ lang, name }] },
  fetchedAt }
```
* `res` = YouTube's resolution label: the number in `qualityLabel` (`"2160p60 HDR"` → 2160; YouTube names a format after the 16:9 / 9:16 frame it fills, so a letterboxed 1920×800 format and a 1080×1920 Short are both 1080), the short side only when there is no label; `height`/`width` = real pixel size (vertical videos: height > width).
* `AYT.videoInfo.blockReason(info)` → localized reason string when downloads are impossible (DRM, live, upcoming, unplayable) else `null`.
* `AYT.videoInfo.fetchCaptions({videoId, lang, kind, vssId, tlang, fmt}) → {body, fmt}` (`fmt`: `json3` (default) | `vtt` | `srv1` | `srv2` | `srv3` | `ttml`). Errors have `.code`: `no_track`, `no_token`, `empty`, `no_player`, `timeout`, `bad_params`, `ad` (an ad is playing and YouTube has given no caption token for this video yet: try again after the ad). The page-side messages are English: show `AYT.captions.errorText(err)`, which maps the code to a translated text.

Called with `AYT.bridge.request(method, params, timeoutMs)`; results are untrusted data.

| method | params | result |
|---|---|---|
| `ping` | – | `{ok, version}` |
| `getPlayerResponse` | `{videoId, surface, timeoutMs}` | pruned player response (null if the player doesn't show that video) |

Events (`AYT.bridge.on(name, fn)`): `ready`, `urlchange {url}`, `videochange {videoId}`, `captions {videoId, lang, kind, tlang, fmt}`.

Captions reality check (verified): `captionTracks[].baseUrl` contains `exp=xpe`; fetching it (any `fmt`) without the player's PO token (`pot`) returns **HTTP 200 with an empty body**. `getCaptions` therefore (1) reuses what the player already loaded (XHR/fetch hooks cache the player's own timedtext responses), (2) retries with the `pot` the player used for this video, (3) briefly switches the player's caption track (hidden, then restored, including YouTube's caption localStorage prefs) so the player fetches it with a valid token. Step 3 is never tried while an ad plays (`ad-showing` / `ad-interrupting`: the player would fetch the ad's captions and the token for the ad): the error is then `ad`, and the subtitles panel retries by itself after the ad. If all fail, the UI falls back to the companion (`kind:'subtitle'` job).

## 7. Service worker (owner: BACKGROUND)

Files: `background/service-worker.js` (entry; classic SW using `importScripts`), plus `background/hub.js` (`AYT.bg`: router errors, UI ports and broadcasts, sender checks, `openOptions`, `openTab`, notifications), `background/task.js` (`AYT.task`: task/meta validation, `buildHostTask`, `checkOutputDir`, cookies.txt), `background/native.js`, `background/jobs.js`, `background/downloads.js`, `background/menus.js`, `background/commands.js`.
`importScripts('../shared/constants.js', '../shared/utils.js', '../shared/i18n.js', '../shared/i18n/en.js', … all 7 …, '../shared/settings.js', 'hub.js', 'task.js', 'native.js', 'jobs.js', 'downloads.js', 'menus.js', 'commands.js')` — all synchronously at top level, and every listener is registered synchronously too (so events wake the worker).
On start, `AYT.bgReady`: `await AYT.settings.load()`, `AYT.i18n.setLanguage(setting)`, then `AYT.native.init()`, `AYT.jobs.init()` and `AYT.menus.ensure()`; every handler awaits it. A language change re-titles the menus, re-localizes job errors and the host status text.

### 7.1 Message router
`chrome.runtime.onMessage` handles every `AYT.MSG.*` (see constants.js comments for payload/response shapes). Always respond `{ok:true,...}` or `{ok:false, error, code}`; return `true` to keep the channel open for async work. Ignore messages whose `sender.id !== chrome.runtime.id` and `__aytPush` messages; unknown types with our prefixes (`host:`, `job:`, …) get `code:'bad_request'`. Validate every field (types, enums, URL hosts, lengths). `HOST_PICK_FOLDER` and `HOST_UPDATE_TOOLS` are accepted only from our own pages and YouTube tabs (`forbidden`). `JOB_START` / `JOB_RETRY` answer `{jobId, job}`, `JOBS_LIST` `{jobs}` and `JOBS_CLEAR` `{removed}` — jobs always as `AYT.jobs.view(job)` (§7.3). Router error codes: `bad_request`, `bad_task`, `bad_state` (retry of an active job), `not_found`, `not_ready` (open before done), `too_many_jobs`, `forbidden`, `internal`, the browser-side download codes of downloads.js (`bad_url`, `bad_filename`, `too_large`, `network`, `fetch_failed`, `decode_failed`, `convert_failed`, `download_failed`) and the host's codes.
`chrome.runtime.onConnect` for port name `AYT.PORT_UI`: once `bgReady`, send `{type: PUSH.JOBS, jobs}` (views) and `{type: PUSH.HOST, status}` (only when known, not `unknown`/`checking`); keep a Set of ports; broadcast `PUSH.JOB` / `PUSH.JOB_REMOVED` / `PUSH.HOST`.

### 7.2 Native host manager (`AYT.native`)
* `status` = `HostStatus = { state: 'unknown'|'checking'|'connected'|'missing'|'forbidden'|'error'|'outdated', version?, protocol?, platform?, tools?: {ytdlp:{version,path,variant}, ffmpeg:{version,path}, deno:{version,path}}, defaultDir?, downloadsDir?, error?, reason?, detail?, checkedAt }`. `error` is a localized text (re-translated on a language change); `reason:'policy'` marks an administrator block. Cache in memory + `chrome.storage.local[AYT.STORAGE.HOST_STATUS]` (written only when it changed); push changes to UI ports.
* `check(force)`: if not forced and checked < 60 s ago, return cached; concurrent calls share one check. Otherwise send `{type:'hello', subfolder}` (through the open port if connected, else `chrome.runtime.sendNativeMessage`; 25 s limit → `error` "didn't answer in time"). Map Chrome's errors: "…host not found." → `missing`; "Access to the native messaging host was disabled by the system administrator." (policies `NativeMessagingBlocklist` / `NativeMessagingUserLevelHosts`) → `forbidden` + `reason:'policy'`, `error` = `background.host.policy`; "Access to the specified native messaging host is forbidden." → `forbidden` (registered for another extension ID), `error` = `background.host.forbidden`; anything else ("Native host has exited." …) → `error` (`background.host.startFailed`: run install.bat again, it sets up Deno, yt-dlp and FFmpeg; Chrome's text in `detail`). A wrong `name` → `error`; `protocol < AYT.PROTOCOL_VERSION` → `outdated`. The options page and the popup show `status.error` for `forbidden` and `error`, like `AYT.ui.hostNotice` (`AYT.pages.hostView` / `hostLine`, §9.5).
* `statusCode(status)` → the job error code for a status that isn't `connected`: `host_missing`, `host_policy`, `host_forbidden`, `host_outdated`, `host_error`.
* Persistent port (`chrome.runtime.connectNative(AYT.HOST_NAME)`) used for jobs; requests are `{id, type, ...}` and correlate with responses `{re:id, ok, ...}`; events `{event, jobId, ...}` go to the jobs module. Request timeout 15 s (pickFolder: 5 min; updateTools: 10 min — the host's own update budget is 9 min, the options page waits 10 min + 20 s). A timed-out `updateTools` stays in flight (`AYT.native.lateCount`), keeping the port open until its late answer (which re-checks the companion: tool versions may have changed), a disconnect, or `config.lateAnswerMs` (10 min). On disconnect: reject pending requests and fail every active job with `host_exit` (`host_missing`/`host_policy`/`host_forbidden`/`host_error` when Chrome says why; canceled jobs end as canceled). Disconnect the port after 20 s with no active jobs and nothing in flight (the host exits on stdin EOF).
* `pickFolder()` → `{path|null}` (params `{title, initial}`); a host failure (`picker_failed`, `busy`) becomes `background.err.pickFailed` + the host's first reason line, which names a blocking PowerShell policy. `updateTools()` → `{output, version, before, after}`; host codes map to `background.err.updateBusy` (`busy`), `updateUnsupported` (`unsupported`), `job.err.ytdlp_missing`, `updateNetwork` (`network`), `updateTimeout` (`update_timeout`: the host did answer, so never `job.err.timeout`) and `updateFailed` (+ the host's reason).

### 7.3 Jobs (`AYT.jobs`)
`Job = { id, kind:'video'|'audio'|'subtitle'|'gif', videoId, title, label, thumbnail, status:'queued'|'starting'|'running'|'processing'|'done'|'error'|'canceled', stage, percent, downloaded, total, speed, eta, playlist:{index,count,title}|null, files:[{path,size}], filePath, fileSize, fileCount, failedItems, error, errorCode, errorDetail, task, meta, createdAt, updatedAt, finishedAt }`. `fileCount` / `failedItems` are set for playlists from the `done` event (`failedItems > 0` = some videos could not be downloaded).
* **UI views:** everything that leaves the service worker (pushes, port snapshots, `JOBS_LIST`, the `JOB_START`/`JOB_RETRY` answers) is `AYT.jobs.view(job)`: the job without `files` (up to 1000 paths for a playlist), `meta`, `errorDetail` and `titlePending`. UIs read `filePath`, `fileSize`, `fileCount`, `failedItems` instead. A tab cannot read the service worker's IndexedDB, so `boot.js` asks `JOBS_LIST` once per tab (its first visible watch page) for the toolbar's progress rings; an open panel's job list gets the port snapshot.
* `start(task, meta, {tabId})` validates the task and meta (§8.3), creates the job (queued) and pumps the queue (`maxConcurrent`, 1..4). A sender tab may have at most `AYT.jobs.config.maxActivePerTab` (20) jobs queued or running → `too_many_jobs`; the popup and the context menu (no tab) are not limited. The stored task keeps only what the UI chose; at dispatch `AYT.task.buildHostTask` adds the settings-derived fields: `outputDir`, `subfolder`, `filenameStyle`, `uiLang`, defaults for `container`/`codec`/`audioFormat`/`bitrate`/`subFormat`/`embed*`, and `cookies` (Netscape cookies.txt text built from `chrome.cookies.getAll({domain:'youtube.com'})` **only if `useCookies` is on**; never stored or pushed). A stored `outputDir` that breaks the folder rules (§8.3) fails the job with `bad_folder` (its notification opens Settings → Downloads).
* Host events update the job (UI pushes ≤ 4/s per job, status changes immediately). Keep at most `AYT.LIMITS.MAX_JOBS_KEPT` (150) jobs. The list is persisted (throttled 1 s; a playlist keeps its last 50 files) in **IndexedDB `ayt-jobs`, store `kv`, key `jobs`**, private to the service worker: a `chrome.storage` write would reach every tab's storage listener. `chrome.storage.local['jobs']` (`AYT.STORAGE.JOBS`) is only the fallback when IndexedDB fails, and a list found there is merged into IndexedDB and removed on start. On service-worker start, jobs that were active are marked `error` with `t('job.interrupted')`, and every other failed job with an `errorCode` is described again (stored again only when its text changed), so an error text saved by an older version loses its paths too.
* `cancel` (queued → canceled immediately; running → host `cancel`, ended as canceled on the host's event or after 20 s), `retry(id, {tabId})` (new job from the same task/meta, also for a partial playlist; removes the old one; same tab limit), `remove`, `clear` (terminal jobs only), `open(jobId, target)` → host `open` with the job's own `filePath` (never a path from the message). Host progress events for a job that was removed, canceled or failed here get a `cancel`.
* Error codes map to friendly strings `job.err.<code>` (`job.err.unknown` for unknown codes) plus the first reason line of the host's detail (`job.error = friendly + ' — ' + reason`; not for `host_*`, `timeout`, `interrupted`, `bad_folder`). `job.error` reaches YouTube tabs, so the reason's absolute paths are hidden with `AYT.util.hidePaths` before its 240-character cut (only a file's own name is left, e.g. `Permission denied: 'x.part'`; a user folder `C:\Users\<name>` becomes `…`); `errorDetail` keeps the host's raw text (≤ 2000 characters) and is never pushed.
* `label(job)` = `AYT.util.jobLabel(job)` (falls back to `job.label`). Action badge = number of active jobs (red). Notifications (`notifyOnComplete`) on done/error; a partial playlist says "Downloaded: N · Failed: M"; clicking a "done" notification opens the file, a `host_*` error opens `#companion`.

### 7.4 Browser-side downloads (`downloads.js`)
* `DOWNLOAD_DATA {dataUrl | (text, mime), filename, kind}` → `chrome.downloads.download({url: dataUrl, filename: AYT.util.downloadsPath(settings.subfolder, sanitizedName), conflictAction:'uniquify', saveAs: settings.askWhereToSave})`.
* `DOWNLOAD_URL {url, filename, convert?}` (only `https://*.ytimg.com/...` or `blob:https://www.youtube.com/...` created by our content script) → direct `chrome.downloads.download`, or fetch + `createImageBitmap` + `OffscreenCanvas.convertToBlob({type, quality:0.95})` + data URL when `convert` is set. A missing `maxresdefault` downloads as an interrupted `SERVER_BAD_CONTENT` → callers should only offer probed URLs.
* Always pass a MIME-consistent name: for data URLs use `AYT.DOWNLOAD_MIME[ext]` (Chrome renames `.srt` saved as `text/plain` to `.txt`); only the extensions listed there can be saved. `chrome.downloads` rejects names containing `: ? " | * < >`, reserved names, leading/trailing dots or spaces, `..` → always run `AYT.util.sanitizeFilename` on the base name (done by `buildFilename`) and `AYT.util.downloadsPath` for subfolders.
* `FETCH_IMAGE {url, convert?}` → `{dataUrl, mime, width, height, bytes}` (same host allowlist).
* `THUMB_PROBE {videoId}` → probe candidates (see MEDIA §9.3), return `{items:[{key, url, width, height, bytes, format}]}` sorted by pixels desc; cache 10 min per video.

### 7.5 Context menus (`menus.js`) and commands (`commands.js`)
* Link context menu on YouTube video links (`*://*.youtube.com/watch*`, `*://youtu.be/*`, `*://*.youtube.com/shorts/*`) and page/video context on watch and Shorts pages: "Download video (best quality)" and "Download audio (MP3)". They start jobs with default settings (video: `height:null` = best).

## 8. Native protocol (service worker ⇄ companion host) (owners: BACKGROUND + COMPANION)

Transport: Chrome native messaging (uint32 little-endian length + UTF-8 JSON). Host → browser messages must stay < 1 MiB (a reply that would not is answered `code:'too_large'`).

* Request: `{ id: string, type: string, ...params }`
* Response: `{ re: id, ok: true, ...result }` or `{ re: id, ok: false, error: string, code?: string }` (any request: `bad_request`, `unknown_type`, `internal`)
* Event: `{ event: string, jobId: string, ... }`

The host handles requests concurrently. Error texts (`error`, event `message`) are English; the service worker shows its own localized text per code (§7.2, §7.3).

### 8.1 Requests
| type | params | result | error codes |
|---|---|---|---|
| `ping` | – | `{}` | |
| `hello` | `{ subfolder?, refresh? }` | `{ name:'akif-youtube-addon-host', version, protocol:1, platform, arch, pid, tools:{ytdlp:{path,version,variant,error?}, ffmpeg:{path,version,error?}, deno:{path,version}}, downloadsDir, defaultDir (= <downloadsDir>\<subfolder>), testMode? }` | |
| `start` | `{ jobId, task }` | `{ outDir }` once the output folder exists and the job was launched | `bad_task` (invalid task, folder can't be created, duplicate `jobId`), `busy` (8 jobs, or yt-dlp is being updated) |
| `cancel` | `{ jobId }` | `{}` (then event `canceled`), or `{ found:false }` for an unknown/finished job | |
| `open` | `{ path, target:'file'\|'folder' }` | `{}` — the path must be absolute and exist; `file` only opens media/subtitle/image extensions | `bad_path`, `not_found`, `open_failed` |
| `pickFolder` | `{ title?, initial?, okLabel? }` | `{ path: string\|null, timedOut? }` | `busy` (already open), `picker_failed` |
| `updateTools` | `{ force? }` | `{ before, after, output, variant, updated }` (also on failure) | `busy`, `unsupported`, `ytdlp_missing`, `network`, `update_timeout`, `update_failed` |

* **start / cancel:** the `jobId` is reserved synchronously, before the output folder is awaited (mkdir on a sleeping or network drive can take seconds). A second `start` with that id gets `bad_task`, also while the first one still waits. A `cancel` during the wait is answered `{}`; the `start` is then answered `{outDir}` as usual, the job never runs, and `canceled` is its only event. The job limit (`MAX_JOBS` 8) and `updateTools`' busy check count reserved starts.
* **updateTools** updates yt-dlp the way it was installed (§9.6) within a 9-minute budget (`UPDATE_BUDGET_MS`; then `update_timeout`) and finishes even after stdin EOF (a half-done update would break yt-dlp). It is refused (`busy`) while this host has jobs running or reserved, or another host instance (Chrome, Edge, any profile; `lib/coord.ts`) runs jobs or an update. The onedir build is re-downloaded from the newest release (tag from the `/releases/latest` redirect, `SHA2-256SUMS` and `yt-dlp_win.zip` from that tag, checksum verified, resumable, test run, folder swap) through `HTTPS_PROXY`, or `HTTP_PROXY` when only that one is set (as yt-dlp does), with `NO_PROXY`; else the static Windows proxy (`ProxyEnable` / `ProxyServer` / `ProxyOverride`; without an `https=` entry https uses the `http=` one, as in yt-dlp; `lib/netproxy.ts`); PAC/WPAD scripts and NTLM/Kerberos proxy sign-in are not supported, and a `network` error ends with "(connected through …)".
* **pickFolder** shows the Windows folder dialog (PowerShell `pick_folder_vista.ps1`). `picker_failed` names what blocked it — an `AllSigned` / `Restricted` execution policy from Group Policy or Constrained Language Mode — and suggests typing the path into "Download folder".

### 8.2 Events
* `info` `{ jobId, title, videoId, duration, uploader, playlistIndex?, playlistCount?, playlistTitle? }`
* `progress` `{ jobId, stage:'video'|'audio'|'download'|'subtitles', percent, downloaded, total, speed, eta, playlistIndex?, playlistCount?, itemPercent? }` — `percent` is the job's overall progress and only goes back when a transient failure is retried; at most 2 events per second per job.
* `stage` `{ jobId, stage:'merge'|'extract'|'thumbnail'|'metadata'|'cut'|'gif'|'subtitles'|'convert'|'processing', percent }` (`percent` = overall progress so far)
* `file` `{ jobId, path, size }`
* `done` `{ jobId, files:[{path,size}], filePath, fileSize, filesTruncated?, fileCount?, failedItems? }` — `files` lists at most 1000 (`filesTruncated: true` when there were more); `filePath`/`fileSize` = the first file (a playlist: `fileSize` = all files). Playlists run with `--ignore-errors` and add `fileCount` (files written) and `failedItems` (items that failed, about one yt-dlp `ERROR:` line each; only when > 0). A playlist with at least one file is `done`.
* `error` `{ jobId, code, message, detail }` — codes: `unavailable, private, age, members, bot, drm, live, format, no_subtitles, forbidden, rate_limited, network, disk, locked, access_denied, ffmpeg, ytdlp_missing, unknown` (classification §8.4). `no_subtitles`: the requested track does not exist or came back empty; `locked`: another program (antivirus, cloud sync) held a file yt-dlp had to open or rename; `access_denied`: Windows refused access (Controlled Folder Access, folder permissions, an app-control policy or antivirus blocking yt-dlp/FFmpeg) — not a full disk.
* `canceled` `{ jobId }`
* Every job ends with exactly one terminal event (`done` | `error` | `canceled`), sent after its temporary folders were removed.
* Codes added by the service worker: `host_missing`, `host_forbidden`, `host_policy`, `host_outdated`, `host_error`, `host_exit`, `timeout`, `interrupted`, `bad_folder`, and the request errors `bad_task` / `busy` of a refused `start`.

### 8.3 Task (validated by the service worker AND again by the host)
```
{
  kind: 'video'|'audio'|'subtitle'|'gif',
  videoId: string(11) | null,
  url: 'https://www.youtube.com/watch?v=<id>' | 'https://www.youtube.com/playlist?list=<id>',
  playlist: boolean,                 // video and audio only
  // added by the service worker from the settings (never taken from a UI message):

The host also accepts `playlistItems` (`"1:5"`, `"1,3,7-9"`; playlists only), which the extension does not send.
Job `meta` (from the UI, display only): `{ title (≤ 300), videoId, thumbnail (https://*.ytimg.com only), label (≤ 200) }`; `label` is only the fallback of `AYT.util.jobLabel` (§3).

**Download folder rules** (the same in the options page `AYT.pages.checkOutputDir`, the service worker `AYT.task.checkOutputDir` and the host `normalizeAbsolutePath` + `MAX_OUTPUT_DIR`): `outputDir` is `''` or an absolute drive (`C:\…`) or UNC (`\\server\share\…`) path, `/` normalized to `\`, without `< > : " | ? *` or control characters, without `.` / `..` segments, names ending in a dot or space, or reserved device names (`con`, `nul`, `com1`…), and **at most 180 characters**, so that `<folder>\<title (clip …)>.<ext>` stays within Windows' 260-character path limit. The options page refuses such a folder when it is saved; a stored value that breaks the rules fails jobs with `bad_folder` in the service worker; the host answers `bad_task`.

### 8.4 yt-dlp mapping (verified on this machine with yt-dlp 2026.10.26 + Deno 2.8.1 + ffmpeg 8.1.1)
Raw evidence was captured under a local working folder during development (not included in this repository).

**Common arguments (every job):**
```

[--ffmpeg-location "<absolute ffmpeg.exe>"]
[--cookies <root>\state\jobs\<pid>-<8hex>\cookies.txt]   (only when task.cookies is set)
[--ignore-errors]   (playlists, embedSubtitles, subtitle jobs)
-- <url>
```
**Job folders** (`lib/tempdirs.ts`; `<root>` = the install folder): the temp dir is `<outputDir>\.akif-tmp\<8 hex>\` (hidden, on the output folder's volume so finishing is a rename; it holds the marker file `.akif-job`), or the private `<root>\state\jobs\<pid>-<8 hex>\` when the output folder is inside a cloud-sync folder (OneDrive, Dropbox, Google Drive, iCloud Drive, Box: `%OneDrive%`, Dropbox's `info.json`, folder names) or its `.akif-tmp` is not a plain folder (junction/symlink). `cookies.txt` is **always** in the private folder, never in the output folder (it may be synced, shared or on a network drive), and exists only while yt-dlp runs. Both folders are removed before the job's terminal event. Leftovers of a killed host are swept: private folders whose host process is gone at host start, `.akif-tmp` job folders with the marker untouched for 12 h by the next job in that output folder (links are never followed).

Facts the host must respect:
* `--print` implies quiet → `--progress` is required; `[AKIF:DL]` lines arrive on **stdout**, `[AKIF:PP]` lines on **stderr**. The `%(.{...})j` object form omits missing keys (a bare `%(x)j` prints `NA`, invalid JSON). Spawn with env `PYTHONIOENCODING=utf-8`, `PYTHONUTF8=1` and always `--encoding utf-8` (otherwise cp1252 silently drops `ə ş` / Cyrillic).
* Never force `--extractor-args youtube:player_client=...` (web/web_safari/mweb/android → SABR / PO-token failures). Defaults (tv + visionos clients) need no PO token.
* Kill with a Windows **Job Object (KILL_ON_JOB_CLOSE)** per job and/or `taskkill /PID <pid> /T /F`. Never `child.kill()` alone: ffmpeg (and the pip launcher's python) survive and keep the pipes open. All partial files live in the job temp dir → delete it on cancel/error/success.
* Idle watchdog: no output for 120 s (30 min while a postprocessor runs) → `network` "The download stalled". One automatic retry for transient failures (`network`, `forbidden`, `locked`, an exit without any output, yt-dlp's "ffmpeg exited with code N" during a section download, an empty clip — which is deleted first): the temp dir is kept, so yt-dlp continues `.part` files and skips finished formats.
* HLS formats: `total_bytes` is NA until finished and `_percent` jumps → compute progress from `fragment_index/fragment_count`, keep it monotonic. Overall percent for merged jobs: (bytes of finished formats + current downloaded) / `filesize_approx` from `[AKIF:INFO]` (fallback: per-stage percent).
* Postprocessor → stage: `Merger→merge`, `ExtractAudio→extract`, `EmbedThumbnail→thumbnail`, `Metadata`/`FFmpegMetadata→metadata`, `SubtitlesConvertor→subtitles`, `VideoConvertor`/`VideoRemuxer→convert`, others (`MoveFiles`, `FixupM4a`, ...) → `processing`.
* Filenames: never `--restrict-filenames` / `--trim-filenames` (destroy Cyrillic/Azerbaijani or the id); use `%(field).NB` byte truncation. yt-dlp replaces `|` → `｜`, `:` → `：` on Windows itself.
* `-J` output can be > 1 MiB (Chrome's host→browser limit): never forward it.

**Output template** (`T` = `%(title).NB` with N = 40…150 bytes, so the final path stays below 250 characters, and the temp path too when Windows long paths are off; `<suffix>` = ` (2160p60 HDR)` for video jobs with a height (YouTube's resolution step for the task's width × height, i.e. the 16:9 / 9:16 frame it fills: `resolutionStep()` in `lib/ytdlp.ts`, the same rule as `AYT.util.jobLabel` (§3), so the file name matches the panel row and the job label: 1920×800 → `(1080p)`, 1080×1920 → `(1080p)`, 4096×2160 → `(2160p)`; the height itself when the task has no width; fps when > 30), plus ` (clip 01-00 - 02-30)` for sections, nothing else for audio):
`title` → `T<suffix>.%(ext)s` · `title_id` → `T [%(id)s]<suffix>.%(ext)s` · `channel_title` → `%(uploader,channel|Unknown).60B - T<suffix>.%(ext)s` · `date_title` → `%(upload_date>%Y-%m-%d|0000-00-00)s T<suffix>.%(ext)s`. Playlists: prefix `%(playlist_title,playlist_id|Playlist).80B\%(playlist_index)03d - `. Files the host finishes itself get the same names: `<base> (clip …).gif`, `<base> (<lang>[→<tlang>]).<ext>` for subtitles.

**Video** (`kind:'video'`):
* Audio part `A`: mp4 or (mkv+compat) → `ba[ext=m4a][language^=L]/ba[ext=m4a]/ba[language^=L]/ba`; webm → `ba[acodec=opus][language^=L]/ba[acodec=opus]/ba`; mkv+auto → `ba[language^=L]/ba` (drop `[language^=L]` parts when no `audioLang`). Never hard-code audio format ids (dubbed videos use suffixed ids like `140-7`, `251-drc`).
* Video filter `V` = `[height=H]` + (`hdr===true` → `[dynamic_range!=SDR]`, `hdr===false` → `[dynamic_range=SDR]`) + (`fps>30` → `[fps>30]` else `[fps<=30]`). Codec preference order: mp4+auto → av01, avc1, vp9 · mp4+compat → avc1, av01, vp9 · webm → vp9, av01 · mkv+auto → av01, vp9, avc1 · mkv+compat → avc1, av01, vp9 (vp9 match = `[vcodec~='^vp0?9']`, others `[vcodec^=avc1]`, `[vcodec^=av01]`).
* Selector (`A` in parentheses) = codec-ordered `bv{V}[vcodec…]+A` alternatives, then `bv{V}+A / bv[height=H]+A / bv[height<=H]+A / b[height<=H] / bv*+ba/b`. Playlists use `[height<=H]` throughout and leave the codec order to yt-dlp's sort. `height:null` → best: `bv*{hdr,fps filters}+A / bv*+A / b` with the codec preference via `-S "vcodec:h264,res,acodec:aac"` only when compat is requested. WebM adds a first alternative restricted to `[vcodec~='^(vp0?9|av0?1)']`.
* `--merge-output-format <container>` (webm: `webm/mkv`; AV1+Opus in MP4 is fine). Embeds: `--embed-metadata` when `embedMetadata`, `--embed-chapters` when `embedChapters` else `--no-embed-chapters` (always explicit: `--embed-metadata` alone also embeds chapters; never chapters for sections: yt-dlp does not shift them, a 10 s clip got all 11 chapters of the 937 s video; audio jobs follow the same rule), `--embed-thumbnail --convert-thumbnails jpg` (mp4/mkv only; without jpg yt-dlp embeds the webp thumbnail as a ~1.4 MB png), `--embed-subs --sub-langs "<uiLang>.*,en.*"` + `--ignore-errors` when `embedSubtitles`.
* Defaults prefer HDR AV1 (e.g. 702 at 4320p): that's why HDR/SDR is explicit in the task.
* Sections: `--download-sections "*S-E"` **plus** `--downloader-args "ffmpeg_i:-request_size 10485760"` (ffmpeg 8.1.1 otherwise HANGS forever on DASH ranges) **plus** `--downloader-args "ffmpeg_o:-progress pipe:1 -stats_period 1"` (parse `out_time_us=`/`progress=` lines on stdout for progress: percent = out_time / (E-S)). `preciseCut` → `--force-keyframes-at-cuts` (exact, re-encodes to x264/aac: slow at 4K/8K — the UI warns). A section download now and then ends without a single video packet: every clip is checked with ffprobe, an empty one is deleted and downloaded once more, and finally fails with `network` "The downloaded clip is empty: YouTube sent no video data for it."; yt-dlp's "ffmpeg exited with code N" there is transient too (`unknown` "FFmpeg stopped while downloading the clip (exit code N)").

**Audio** (`kind:'audio'`): `-f` `ba[language^=L]/ba/b` (m4a target: `ba[ext=m4a][language^=L]/ba[ext=m4a]/…` first; opus target: `ba[acodec=opus]…` first — same-codec targets are copied, not re-encoded) `-x --audio-format <fmt>`; mp3 adds `--audio-quality <bitrate>K`; `--embed-metadata` when `embedMetadata`; `--embed-thumbnail --convert-thumbnails jpg` for mp3/m4a/opus/flac **never for wav** (fatal error). Exact sections: no `--download-sections` (stream-copy sections are NOT exact: 3–9 s came out as 9 s). m4a (left untouched by ExtractAudio) → download whole, then the host cuts with `ffmpeg -ss S -to E -i in -map 0:a -map 0:v? -map_metadata 0 -c copy out` (stage `cut`); every other format → `--ppa "ExtractAudio+ffmpeg_o:-ss S -to E"` (cut inside ExtractAudio's one ffmpeg run, before the cover is embedded).

**Subtitle** (`kind:'subtitle'`, companion fallback): `--skip-download --write-subs|--write-auto-subs --sub-langs "<keys>" --sub-format "<fmt>/best" --ignore-errors` and `--print "after_video:[AKIF:SUBS] %(requested_subtitles.:.{ext,filepath})j"` (after_move doesn't fire with --skip-download). Keys: manual → `<lang>`; auto original → `<lang>-orig,<lang>`; translated → `<tlang>-<lang>,<tlang>` (YouTube currently answers HTTP 429 for translated auto-captions → error code `rate_limited`). `srt` and `txt` download `json3/vtt/best` and the host converts (`lib/subs.ts`: clean cues, no rolling duplicates). No file → `no_subtitles`.

**GIF** (`kind:'gif'`, section ≤ 60 s): download `-f "bv[ext=mp4]/bv/b" -S "res:<480, or 720 when gifWidth > 480>"` with the section args above into the temp dir, then `ffmpeg -y -i clip -vf "fps=<gifFps>,scale='min(<gifWidth>,iw)':-1:flags=lanczos,split[s0][s1];[s0]palettegen=max_colors=128:stats_mode=diff[p];[s1][p]paletteuse=dither=bayer:bayer_scale=3:diff_mode=rectangle" -loop 0 out.gif` (stage `gif`) and move it into the output dir (~0.6–1 MB per second).

**Error classification** (`lib/errors.ts`; the `ERROR:` lines, else the warnings and the output tail; first match wins): "Sign in to confirm your age"/"age-restricted" → `age`; "Sign in to confirm you’re not a bot" → `bot`; "Private video" → `private`; "members-only"/"Join this channel" → `members`; "DRM" → `drm`; "live event will begin"/"Premieres in"/"is live" → `live`; "Video unavailable"/"This video is unavailable"/"not available in your country"/"playlist does not exist" → `unavailable`; "Requested format is not available" → `format`; "HTTP Error 429" → `rate_limited`; "HTTP Error 403" → `forbidden`; "No space left"/"Errno 28" → `disk`; "WinError 32"/"being used by another process" → `locked`; "WinError 5"/"Errno 13"/"Access is denied" → `access_denied` (also when Windows refuses to start yt-dlp/FFmpeg or to write the output folder); "ffmpeg not found"/"ffprobe not found" → `ffmpeg`; timeouts / "getaddrinfo" / "Connection" / SSL errors → `network`; else `unknown`. Missing tools: `ytdlp_missing` / `ffmpeg` ("Run install.bat again"). Exit code 127 with empty output happened once and succeeded on retry → retried once automatically (see the transient list above).

### 9.6a Verified behaviors that change module code (all from research, Nov 2026)
* **Screenshots:** the `<video>` canvas is not tainted. Drawing right after a resolution switch yields an all-black frame → when the video is playing, wait for one `video.requestVideoFrameCallback` (timeout 300 ms) before `drawImage`. During ads (`AYT.player.isAdPlaying()`) the `<video>` shows the ad → refuse with a toast. Save via a **blob URL** (`URL.createObjectURL` in the content script) sent with `DOWNLOAD_URL` (the service worker can download page blob URLs; revoke after 60 s) — no data-URL size limits.
* **Subtitles:** with the PO token every native format works, so request the user's format directly: `fetchCaptions({..., fmt:'vtt'|'ttml'|'srv3'|'json3'})`; build SRT and TXT from `json3`. Translation = `tlang`. Use `AYT.DOWNLOAD_MIME` when downloading (Chrome renames `.srt` to `.txt` with `text/plain`).
* **Clipboard:** image copy works in a click handler; keyboard-command copies rely on the `clipboardWrite` permission (present). The page must be focused.
* **A-B loop:** the player has a native `setLoopRange({startTimeMs,endTimeMs})` → bridge `setLoopRange({start,end})` (seconds) / `setLoopRange({start:null,end:null})` to clear; fall back to a manual seek loop only if `supported:false`.
* **Speed:** `setPlaybackRate` in YouTube's API clamps to 0.25–2; the bridge sets `<video>.playbackRate` directly above 2 (max 16; 17 throws). YouTube's own UI keeps showing 1× in that case.
* **Volume:** `setVolume` caps at 100 → boost needs Web Audio.
* **Quality:** `getAvailableQualityLevels()` may hide 4320p/HDR that exist in adaptiveFormats; trust `<video>.videoHeight`.
* **Shorts:** no `[is-active]`; one `ytd-reel-video-renderer` moves between slots; the action column `reel-action-bar-view-model` (children: like-button-view-model, button-view-model×4 (comments, share, remix, more), pivot-button-view-model) is **re-created on every swipe** → re-inject on `yt-navigate-finish` + a MutationObserver scoped to `ytd-shorts`. Insert our button before `:scope > pivot-button-view-model` (or append). Player: `#shorts-player`.
* **Commands:** Chrome silently drops suggested shortcuts that collide with its own Alt+Shift+{A,B,C,I,N,P,R,T,W,X,Z}; cinema mode therefore uses Alt+Shift+M.
* **Service worker:** an idle content-script port dies after 30 s (SW terminated) — reconnect logic lives in `AYT.client`; ports with traffic every < 30 s keep it alive; a connected native port keeps it alive too.
* **i18n:** Chrome has no Azerbaijani UI locale, so `chrome.i18n.getUILanguage()` never gives `az` for normal users → our own language setting, and `'auto'` looks at Chrome's preferred languages (`navigator.languages`) first (§3). `lang` attributes are set on our roots so CSS `text-transform: uppercase` handles Turkish/Azerbaijani `i/İ`.

See §8 for the protocol and §8.4 for yt-dlp arguments; user-facing details are in `companion/README.md`. Deliverables: `companion/host/host.ts` + `host/lib/*`, `companion/host/host.bat`, `companion/install.ps1` + `install.bat`, `companion/uninstall.ps1` + `uninstall.bat`, `companion/tests/*` (unit tests, plus protocol and real download tests that actually pass on this machine). **Installer** (`install.bat` → `install.ps1`; a re-run updates or repairs in place):
* Layout: `%LOCALAPPDATA%\AkifYouTubeAddon\{host\host.ts, host\host.bat, host\lib\…, bin\deno.exe (+ yt-dlp / FFmpeg when downloaded), state\, logs\host.log, config.json (absolute tool paths, UTF-8), com.akif.youtube_addon.json, .akif-companion-install, uninstall.ps1/.bat}`. The host runs with the user's rights, so `-InstallDir` must be inside the user's profile and not be (or be inside) a link; a parent that other accounts can rename, or an existing installation they can change, is refused; otherwise the write access of other accounts is removed from the folder.
* The extension ID is computed from `extension/manifest.json` `key` (sha256 → first 32 hex → a–p); the host manifest has `allowed_origins: ["chrome-extension://<id>/"]` and is registered under HKCU for Chrome, Edge and Chromium. The installer warns when a browser policy blocks it (`NativeMessagingUserLevelHosts` = 0, the host on the `NativeMessagingBlocklist`) and refuses to run elevated as another account than the desktop's user ("Run as administrator" with another administrator's password would install for that account; `-Force` overrides).
* Tools: reuse a working yt-dlp ≥ 2025.11 from PATH (variants `pip` — only when it has `yt-dlp-ejs`, which solves YouTube's JavaScript challenges —, `winget`, `exe`), FFmpeg from PATH when `ffprobe` sits next to it and it supports `-stats_period` and the http option `request_size` (every clip, GIF and cut needs both), and copy Deno ≥ 2.0 from PATH into `bin\` (package-manager shims are resolved to the real deno.exe). Otherwise the official builds go into `bin\`; yt-dlp as the onedir `yt-dlp_win.zip` (variant `onedir`; the one-file `yt-dlp.exe` starts 2–4× slower and leaks ~29 MB `%TEMP%\_MEI*` per forced kill).
* Downloads are release-pinned and fail closed: all files of a tool come from one release (yt-dlp and Deno: the tag named by the `/releases/latest` redirect; FFmpeg: the rolling `latest` build of `yt-dlp/FFmpeg-Builds` with its `checksums.sha256`) and must match the SHA-256 published with it; a downloaded `deno.exe` must also carry a valid Authenticode signature of Deno Land Inc.
* A re-run keeps working copies in `bin\`: yt-dlp and Deno are replaced only by a newer release, FFmpeg (a daily build) only with `-Redownload`, and a tool whose newest release can't be looked up is kept — so a re-run downloads nothing it already has and works offline. Options: `-InstallDir`, `-OwnYtDlp`, `-OwnFfmpeg`, `-OwnDeno` (use `bin\` even when PATH has the tool), `-Redownload`, `-NoRegister`, `-SkipSelfTest`, `-Force`.
* The installed files are unblocked (the mark of the web would make `RemoteSigned` refuse the folder-picker script). An `AllSigned` / `Restricted` execution policy set by Group Policy and Constrained Language Mode (AppLocker / WDAC) are not supported; `install.bat`, `uninstall.bat` and the scripts say so.
* Finally it self-tests the host the way the browser starts it (framed `hello`), which also pre-warms the Deno cache (the first start after an install can take seconds because of Defender).
* `uninstall.ps1` only touches a folder with the marker `.akif-companion-install` (or `config.json` + the host manifest), deletes only what the installer created, and removes only the browser registrations that point to that folder.

**Companion implementation notes (verified by research):**
* `companion/host/lib/`: `guard.ts` (must be the FIRST import: stops anything from writing to stdout), `log.ts`, `nm_io.ts` (framing, write-all, 1 MiB guard), `proc.ts` (spawn with `stdin:'null'`, piped stdout/stderr, line splitter for `\n`/`\r\n`/`\r`, Job Object via FFI + taskkill fallback), `winshell.ts` (SHOpenFolderAndSelectItems reveal, ShellExecuteW open, SHGetKnownFolderPath Downloads — all via FFI — and the folder picker), `ps/pick_folder_vista.ps1` (IFileOpenDialog folder picker, TopMost owner, inputs via env vars, raw UTF-8 JSON output), `task.ts` (task validation), `starts.ts` (start/cancel), `jobs.ts`, `ytdlp.ts` (arguments), `progress.ts`, `errors.ts`, `subs.ts`, `tempdirs.ts`, `tools.ts` (versions, updates), `netproxy.ts`, `coord.ts` (jobs/updates across host instances), `config.ts`, `paths.ts`. Chrome-launch emulator + tests: `companion/tests/nmsim.py`, `protocol_test.py`, `unit_test.ts`.
* Chrome launches every host as `%COMSPEC% /d /s /c ""<dir>\host.bat" chrome-extension://<id>/ --parent-window=0" < \\.\pipe\… > \\.\pipe\…` (hidden console, cwd = host dir). On disconnect Chrome kills **only cmd.exe** after 2 s → the host must exit on stdin EOF and kill all job trees itself (Job Objects also cover a host crash).
* `host.bat`: pure ASCII, CRLF, **no BOM**, first line `@echo off`, never echo anything; `setlocal EnableExtensions DisableDelayedExpansion`; env `DENO_NO_UPDATE_CHECK=1`, `DENO_NO_PROMPT=1`, `NO_COLOR=1`, `DENO_TLS_CA_STORE=system,mozilla` (trust the Windows store, where TLS-inspecting company proxies put their root certificate), `DENO_DIR=%~dp0.deno-cache`; `HOST_DENO=%~dp0..\bin\deno.exe` (else `deno.exe` from PATH); error-log redirect probe `(type nul >>"%HOST_ERRLOG%") 2>nul || set "HOST_ERRLOG=NUL"`; run line `"%HOST_DENO%" run --quiet --no-config --no-lock --no-prompt --no-remote --no-npm --allow-all "%~dp0host.ts" %* 2>>"%HOST_ERRLOG%" & exit /b`. cmd.exe re-reads the .bat after every command, so an instance still waiting for deno must end on that line when install.bat overwrites the file; instances of the first release resume at byte 1126, so the deno line must end exactly there (comments in the file). Never embed non-ASCII absolute paths in the .bat (use `%~dp0`-relative paths) — therefore the installer puts a copy of deno.exe into `bin\` (copy from the PATH install, or download).
* `Deno.Command(...).spawn()` inherits stdio by default (corrupts Chrome's pipe): always `stdin:'null', stdout:'piped', stderr:'piped'`.
* Explorer: never await `explorer.exe` (exit code is always 1 and it can hang); use the FFI helpers. `cmd /c start` expands `%VAR%` inside quotes — don't use it.
* Install dir must not contain `& ^ | < >` (cmd parsing): `%LOCALAPPDATA%\AkifYouTubeAddon` is fine. Host manifest JSON must be written as UTF-8 **without** BOM (PowerShell 5.1 `Out-File`/`Set-Content` default to UTF-16/ANSI → use `[IO.File]::WriteAllText(path, text, (New-Object Text.UTF8Encoding $false))`). `.ps1` files: ASCII only (PS 5.1 reads BOM-less files as ANSI).
* Registry (HKCU, default value = absolute manifest path): `Software\Google\Chrome\NativeMessagingHosts\com.akif.youtube_addon` (read by Chrome; also by Brave/Chromium/CfT as fallback, and by Edge as last fallback; probably Vivaldi/Opera), `Software\Microsoft\Edge\NativeMessagingHosts\…`, `Software\Chromium\NativeMessagingHosts\…`.
* yt-dlp on this machine is a **pip** install (`Python311\Scripts\yt-dlp.exe` launcher → python.exe), with curl_cffi + yt-dlp-ejs; deno/ffmpeg are WinGet symlinks. `updateTools` per variant: pip → `<python> -m pip install --upgrade --disable-pip-version-check --no-input "yt-dlp[default]"`; exe → `yt-dlp -U`; winget → `winget upgrade -e --id yt-dlp.yt-dlp …`; onedir → the verified re-download of §8.1 (`yt-dlp -U` refuses unpackaged builds; the installed zip's hash is kept in `state\ytdlp-onedir.sha256`, so an up-to-date build is not downloaded again); the outcome text is reported.
* FFmpeg downloads: `ffmpeg-master-latest-win64-gpl.zip` (`ffmpeg.exe` + `ffprobe.exe` into `bin\`); Deno: `deno-x86_64-pc-windows-msvc.zip`. The host passes `--js-runtimes "deno:<bin\deno.exe>"` and `--ffmpeg-location` from `config.json` (re-read every minute and on `hello`, so a re-install is picked up).
